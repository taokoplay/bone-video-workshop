# bone-video-workshop — Bone 影视工厂

[English](README.md) | 简体中文

Bone 影视工厂是独立运行于 **PI-Desktop** 的影像创作插件，支持漫剧、影片、宣传片和图片作品。Agent 通过工具保存创作内容，工作台负责浏览剧本、资产、分镜、素材、剪辑方案及评审记录。

- 插件 ID：`bone.video.workshop`
- 当前版本：`0.21.0`
- 源码目录：`bone-video-workshop`；目录名与插件 ID 分别管理。
- 许可证：[AGPL-3.0-only](LICENSE)，与 PI-Desktop 宿主仓库独立维护。

插件提供创作管理和素材预览，本身不生成图片、声音或视频。生成需要使用宿主中实际可用、已获授权的工具，也可以导入已有文件。

## 主要能力

| 能力 | 说明 |
|---|---|
| 项目设定 | 保存世界背景、规则、历史时间线与全剧主线 |
| 剧本正文 | 保存有场次、可见动作、人物反应和完整对白的 `prose` |
| 脚本节拍 | 将正文拆解为结构化 `beats`，再映射到实际镜头 |
| 资产管理 | 管理角色、场景、道具、首尾帧与声音；分别保存档案和生成提示词 |
| 分镜与制作计划 | 保存画面、运镜、对白、声音、连续性和生成留量计划 |
| 媒体登记与采用 | 导入真实文件，显式绑定到资产或镜头的图片、视频、音频槽位 |
| 剪辑与预览 | 保存素材选区、恒定倍速、独立音轨和切点说明，预览连续片段 |
| 证据评审 | 保存有明确范围的结论，区分有效、过期及已被新结论替代的记录 |
| 修订与恢复 | 先保存逐字段差异，授权后应用；满足条件时恢复，并保留历史 |

## 安装与开始使用

安装包下载、开发加载、升级和数据备份步骤见[安装升级指南](docs/installation-upgrade.md#中文说明)。

### 开发目录加载

```bash
git clone https://github.com/taokoplay/bone-video-workshop.git
cd bone-video-workshop
```

1. 在 PI-Desktop 的插件管理中，将包含 `manifest.json` 的项目根目录加载为开发插件。
2. 按宿主提示审核插件权限。更新已加载的开发插件后，可使用 **Plugins → More → Reload** 重新加载。
3. 从工作面板菜单或全局命令搜索中打开 **Bone 影视工厂**。
4. 向 Agent 发出创作请求。Agent 保存内容后，点击工作台的“刷新”查看结果。

### 安装包加载

也可以安装打包生成的 `.piplug` 文件。生成方式见下方“开发、验证与打包”。`dist/` 不纳入 Git，克隆源码不会自带安装包；不要将文件夹名或插件 ID 改成版本号。

### 请求示例

**创建剧本与分镜：**

> 在 Bone 影视工厂创建一部三集漫剧，每集约一分钟。先建立世界背景、规则、人物档案和三集主线，再完成第一集可拍摄的完整剧本、脚本节拍和分镜计划。本次先做到文字与计划阶段。

**只评审：**

> 评审这部作品第一集的剧本可拍性、人物知情范围、对白时长与相邻镜头连续性。列出证据、影响和最小修改建议，保存评审记录，不改写正文、资产或分镜。

**只提出修订方案：**

> 根据当前有效评审提出修订方案，展示修改前后、必须保留的内容和验收条件。先保存方案并回读，不执行应用。

**执行具体方案：**

> 应用刚才确认的修订方案，范围仅限已列出的字段。先检查最新版本与差异，成功后回读并复核受影响镜头，不生成媒体。

实际工具调用必须使用作品中真实的 ID。工具名可能由宿主加上插件前缀，应以当前可发现的工具名称为准。

## 推荐创作流程

1. **读取现状**：调用 `list_productions`、`get_production` 和 `get_workflow_status`，了解已保存内容与缺口。
2. **建立项目设定**：保存背景、规则、时间线、主线和角色档案。多集作品先完成全剧规划，再展开单集。
3. **写完整剧本**：在 `prose` 中写齐有序场次、动作、反应和完整对白，篇幅服从目标时长。
4. **拆解脚本节拍**：用 `beats` 记录叙事功能、观众问题、事件变化、视觉动作、对白意图、声音与连续性。
5. **建立资产与分镜**：角色、场景和道具使用稳定资产；每个镜头归属一个真实节拍，一个节拍可以对应多个镜头。
6. **完善制作计划**：分别规划视频模式、声音、镜头衔接、生成长度与头尾留量。
7. **制作并导入素材**：使用可用生成工具或已有文件，先登记，再明确采用；未采用的素材可以保留为候选。
8. **测量、剪辑与评审**：核对真实源片，保存入出点和音轨，预览连续片段，依据实际观察记录结论。
9. **按授权修订**：评审、提案、应用和复核分别完成。结束时再次检查工作流状态并说明剩余事项。

**剧本 `prose` 与脚本 `beats` 不能互相替代。** 一句话梗概、节拍表或分集大纲不是完整可拍摄剧本。插件也不要求所有题材套用固定字数、固定场次数或固定反转比例。

## 工作台页面

| 页面 | 内容 |
|---|---|
| 项目 | 基本设定、背景、规则、时间线、全剧主线与资产库 |
| 剧本 | 连续的完整正文 `prose` |
| 脚本 | 结构化叙事节拍 `beats` |
| 分镜 | 镜头序列、媒体预览、首尾帧、声音、引用资产、制作计划与剪辑记录 |
| 制作配置 | 工作流缺口、预算偏差、制作状态以及评审与修订方案 |

剧本、脚本和分镜共享集数选择。点击资产图片或名称可打开详情弹窗，查看介绍、人物档案、提示词和素材。图片支持放大；音视频支持播放、暂停和拖动进度。

浏览与复制指令不会修改作品。复制按钮不会发送聊天消息，也不会启动生成或执行修订。已有的新建、基本设定编辑和删除入口仍保留显式操作。

## 项目设定与人物档案

| 内容 | 保存字段 | 长度上限 |
|---|---|---:|
| 世界背景 | `projectBible.background` | 20,000 字符 |
| 世界规则 | `projectBible.rules` | 20,000 字符 |
| 历史时间线 | `projectBible.timeline` | 20,000 字符 |
| 全剧主线 | `arc` | 4,000 字符 |
| 资产简介 | `description` | 2,000 字符 |
| 人物档案／资产详细设定 | `profile` | 20,000 字符 |
| 生图提示词 | `imagePrompt` | 8,000 字符 |
| 避免项与一致性约束 | `negativePrompt` | 8,000 字符 |

人物目标、动机、秘密、关系和成长线应写到各角色资产的 `profile`。生成提示词与人物档案分开保存。声音资产不要求填写生图提示词。

旧版集中人物资料 `projectBible.characters` 仍保留，可在资产区打开查看。归档指令先提出与现有档案合并的方案；不会自动拆分角色、覆盖已有档案或清空旧内容。

更新设定和资产时，省略字段表示保留，显式空字符串表示清空对应字段。非法类型与超限内容会被拒绝，不应依赖自动截断。详细分集规划和证据报告可放在工作区的 `bone-projects/<productionId>/`，但核心设定应保存到插件原生字段。

## 时长与制作计划

以下数值用途不同，应分别保存：

| 数据 | 含义 |
|---|---|
| 镜头 `duration` | 成片剪辑预算，保留小数秒 |
| `generationDurationSeconds` | 计划申请的生成源片长度 |
| `headHandleSeconds` / `tailHandleSeconds` | 期望动作前后可剪留量，生成后仍需核实 |
| `record_media_inspection.durationSeconds` | 对真实媒体的测时报告 |
| 剪辑方案 `inSeconds` / `outSeconds` / `speed` | 实际采用的源片选区与恒定倍速 |

生成源片可以长于成片采用段。源片长度不参与成片预算求和；无效动作、穿帮或错误对白也不能算作可用留量。

镜头的 `productionPlan` 记录场次、叙事任务、必需事件、生成长度、留量和变速限制。`videoPlan`、`soundDesign`、`continuityPlan` 分别记录生成模式、声音和衔接。上述嵌套计划整体替换：省略保留，传 `null` 清除。

## 素材登记与采用

1. 将真实文件放到当前工作区的 `bone-media/<productionId>/` 下。
2. 使用 `register_media` 导入。登记不会自动采用素材。
3. 使用 `adopt_media` 将素材绑定到一个资产，或一个镜头的相应输出槽位。
4. 刷新面板，检查真实图片、音频或视频能否正常预览。

镜头专属素材需要携带生成时对应的镜头版本。导入和采用时使用当前要求的 `expectedShotRevision`，不能把旧版本素材伪装成新版本结果。采用图片、视频和音频时，各输出槽位相互独立。

支持的文件签名与大小限制：

- 图片：PNG、JPEG、GIF、WebP，最大 32 MiB。
- 视频：MP4、WebM，最大 64 MiB。
- 音频：WAV、MP3、Ogg，最大 64 MiB。
- 每个作品最多登记 1,024 条媒体记录。

签名识别不保证浏览器支持文件内的编码，预览时仍需实际解码。导入内容按字节去重，保留原始来源；锁定资产与镜头版本检查不会被跳过。

## 剪辑、预览与评审

`record_media_inspection` 保存素材 SHA 对应的测时、方法、发现和可用范围。它是 Agent 报告的观察结果，不代表宿主认证已完整观看或收听。

`save_edit_plan` 保存有序视频选段、恒定倍速、源音频使用方式、独立音轨与相邻切点说明。它需要当前作品版本和剪辑方案版本。保存不会覆盖源文件、采用输出或导出影片。

面板可预览连续 **1–8 个片段**，不同源文件总量最多 192 MiB，支持硬切、选区、恒定倍速和独立音轨叠加。预览不是逐帧精确的离线渲染，也不执行描述文字中的叠化、变速曲线等效果。

评审结论包括：

- `supported`：已观察范围内的证据支持该结论。
- `needs-revision`：存在有依据的修订需求。
- `not-verified`：缺少足够证据，尚未验证。

评审可针对剧集、镜头、已保存的切点或序列，类别包括文本、技术、视觉、音频和连续性。相关内容或素材依据变化后，结论会过期；新结论可以替代同范围同类别的旧结论，但不会删除历史。

`get_workflow_status.complete` 只表示结构和必要输出关联完整，不代表艺术质量通过、最终影片已导出或所有编码均可播放。没有真实声画时，只能完成文本与计划层面的检查。

## 评审、修订与恢复

标准顺序为：

**评审 → 保存具体修订方案 → 回读差异 → 在授权范围内应用 → 回读复核 → 必要时条件恢复**

修订方案包含修改意图、真实目标 ID、逐字段修改前后值、问题来源、理由、保留约束和验收条件。修改前值由插件读取保存，不由 Agent 猜测。

| 修订意图 | 主要范围 |
|---|---|
| `wording` | 剧集文字、部分节拍文字与镜头对白 |
| `visual` | 镜头画面、运镜、视频／声音／连续性计划及资产生图提示词 |
| `pacing` | 镜头时长、制作留量计划及剧集目标时长／制作说明 |
| `story` | 允许字段内的跨项目、剧集、节拍、资产和镜头关联修改 |

字段限制不能自动判断改写是否保持原意，Agent 仍需核对保留约束。

- `save_revision_plan` 只保存方案，不改正文、资产、镜头或素材绑定。
- `apply_revision_plan` 检查版本、内容基线、引用评审与锁定状态后，原子应用方案。
- `restore_revision_plan` 仅在应用后内容基线仍匹配时恢复对应字段；后续内容变更会阻止恢复，避免覆盖新修改。
- 应用与恢复都保留素材、评审及输出历史，镜头版本持续递增。恢复原文不会使旧素材或已失效评审重新有效。
- 应用不代表问题已经解决，必须按原验收条件重新检查。

应用和恢复需要 `confirm: true`、当前作品版本及真实的授权说明。这些参数是 Agent 对用户授权的陈述，不能替代宿主权限检查。已有直接编辑工具仍兼容，修订工作流不是拦截所有写入的安全沙箱。

每个作品最多保存 40 个方案，每个方案最多 100 项修改，单个 `replacementJson` 最多 220,000 字符，完整记录最多 2 MiB（包含后续应用／恢复元数据）。超限操作会拒绝，不自动删除历史。当前修订方案不负责新建、删除、重排对象或修改 ID、素材绑定。

## Agent 工具一览

| 工具 | 用途 |
|---|---|
| `list_productions` | 列出作品与数量信息 |
| `get_production` | 读取设定、正文、节拍、资产、镜头、素材及评审修订记录 |
| `get_workflow_status` | 检查创作链缺口、制作状态和下一步 |
| `create_production` | 创建作品及初始设定 |
| `update_production` | 更新基本设定、项目设定集与主线 |
| `write_script` | 写入或更新单集完整剧本正文 |
| `write_episodes` | 写入多集内容与有序节拍 |
| `add_assets` | 登记角色、场景、道具等资产 |
| `update_asset` | 更新资产资料、提示词或锁定状态 |
| `delete_asset` | 删除符合引用检查条件的资产 |
| `add_shots` | 创建关联真实节拍的镜头 |
| `update_shot` | 更新镜头内容、计划或节拍映射 |
| `move_shot` | 调整镜头顺序 |
| `delete_shot` | 删除镜头及相关映射、状态 |
| `register_media` | 导入真实工作区媒体文件 |
| `adopt_media` | 将已登记素材绑定到资产或镜头输出 |
| `delete_production` | 永久删除作品，需要明确确认 |
| `record_media_inspection` | 保存与素材 SHA 对应的测时和可用范围报告 |
| `save_edit_plan` | 保存剪辑选区、倍速、独立音轨与切点说明 |
| `record_review` | 保存有范围、有证据的评审结论 |
| `save_revision_plan` | 暂存逐字段修订方案 |
| `get_revision_plan` | 读取修订差异与当前可应用／恢复状态 |
| `apply_revision_plan` | 在授权和版本检查后应用方案 |
| `restore_revision_plan` | 在条件满足时恢复方案对应字段 |

`write_episodes` 的 `beats` 数组整体替换原列表，修改时应带上需要保留的节拍及其真实 `beatId`。镜头跨集移动时，必须同时指定目标集的节拍。

## 数据与权限

作品和媒体保存在宿主提供的插件私有目录：

```text
<plugin data path>/productions/<productionId>/snapshot.json
<plugin data path>/productions/<productionId>/media/<content hash>.<extension>
```

写入按作品串行处理，通过原子替换保存，并递增作品版本。旧快照保持可读；缺少新字段时显示缺口，不会自动改写旧作品。

| 权限 | 用途 |
|---|---|
| `ui.view` | 显示工作台 |
| `agent.tool.register` | 注册 24 个创作工具 |
| `agent.prompt.inject` | 按需发现和加载创作技能 |
| `fs.read` | 从工作区 `bone-media/**` 范围读取导入素材 |
| `clipboard.write` | 复制 ID 和 Agent 指令 |

源码目录、宿主安装目录和作品数据目录分别管理。不要通过改写私有快照或宿主权限登记文件绕过工具与权限检查。

## 开发、验证与打包

插件使用原生 JavaScript、HTML 和 CSS，无需前端构建。测试使用 Node.js 内置测试运行器；需要支持 `structuredClone` 等当前实现所用 API 的 Node.js 环境。现有验证使用 Node.js 24。

在插件根目录执行：

```bash
node scripts/sync-manifest.cjs --check
node --test tests/*.test.cjs
```

修改工具声明或版本后，用以下命令同步 `manifest.json` 和页面版本标记：

```bash
node scripts/sync-manifest.cjs --write
```

使用已经配置好开发环境的 PI-Desktop 源码仓库，在宿主仓库根目录执行（将路径替换为实际插件目录）：

```bash
pnpm pi-plugin check /path/to/PI-Plugins/bone-video-workshop
pnpm pi-plugin pack /path/to/PI-Plugins/bone-video-workshop
```

安装包写入插件的 `dist/`，命名为 `bone.video.workshop-<version>.piplug`。`pi-plugin` 是宿主提供的开发命令，单独克隆本插件不会安装该命令。

浏览器测试需要 Python Playwright、可用的 Chrome，以及隔离的工作台桥接测试页面。该页面需要提供测试快照、媒体和复制记录；下列命令不是直接对正式作品运行：

```bash
python3 tests/project-bible.browser.py /path/to/isolated-harness.html
python3 tests/project-scroll.browser.py /path/to/isolated-harness.html
python3 tests/revisions.browser.py /path/to/isolated-harness.html
```

仓库包含浏览器测试脚本，未提供一键构建所有隔离页面的命令。不要用真实作品、正在运行的用户 Agent 或付费生成服务代替隔离测试环境。
